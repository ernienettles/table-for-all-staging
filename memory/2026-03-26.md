
## Session: Table for All WordPress Rebuild (post-compaction)

### What happened
Ernie was frustrated that the site looked "smooshed" — GeneratePress theme + custom templates overlapping. We rebuilt all 7 pages as completely standalone custom HTML templates.

### Key technical discovery
SiteGround uses **nginx caching** at the server level that bypasses WordPress entirely for cached requests. ALL pages showed stale cached HTML until we added a unique query string (e.g., `?nocache=1`). This is why early tests kept showing the old GeneratePress output.

### Final architecture
- **Custom PHP templates** in `table-for-all/` child theme — `tpl-*.php` files
- Hook: `template_redirect` at priority -999 intercepts our page IDs, includes the standalone template, `exit`
- WordPress still loads (post ID 46394 is queried — unrelated blog post) but our hook intercepts correct pages
- No `get_header()`, no `get_footer()`, no GeneratePress wrapper — full HTML per page
- SiteGround nginx caching means live site needs `?nocache=` query string for testing
