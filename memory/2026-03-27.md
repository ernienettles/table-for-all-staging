### Elementor Data Encoding (CRITICAL)
- WordPress stores _elementor_data as: serialize(JSON.stringify(elementorArray))
- Double-encoded: PHP serialize() WRAPPED around a JSON-encoded string
- WP-CLI `wp post meta get --format=json` returns the outer serialize wrapper as a JSON string
- To decode: json.loads() once → gives the JSON-encoded string; json.loads() again → gives the array
- To encode for storage: json.dumps(string) → gives JSON-encoded string; WordPress serializes it when storing via wpdb
- IMPORTANT: The inner JSON uses \uXXXX notation for Unicode (curly apostrophes as \u2019, em-dash as \u2014)

### Elementor Corruption Issue
- PHP str_replace on the raw meta value corrupts the JSON if search/replace strings don't exactly match (encoding mismatch)
- Safe approach (confirmed working): Python on LOCAL machine → pull via WP-CLI → modify outer JSON string with Python str.replace() → push via PHP/wpdb directly
- Do NOT use PHP str_replace on the meta value — encoding differences cause silent JSON corruption
- Also: function name collision with PHP built-in `strip_tags` in PHP scripts — use custom names
