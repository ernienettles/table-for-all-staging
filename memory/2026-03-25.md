## chat.send RESOLVED — ws-proxy Architecture

**Problem:** Browser WebSocket can't do device auth (private key never leaves server). Token auth only gives `operator.read`.

**Solution:** `ws-proxy.cjs` — standalone WebSocket proxy on `ws://127.0.0.1:8090`

- Proxy runs as Ernie's user → reads device private key from `~/.openclaw/identity/`
- Uses RSA challenge-response to authenticate with gateway as `gateway-client` with `operator.write`
- Browser connects to proxy WITHOUT auth → proxy handles gateway auth internally
- Proxy ID-maps browser message IDs to proxy IDs for response routing
- Started automatically by `start.sh` before Vite dev server

**Architecture:**
```
Browser → ws://127.0.0.1:8090 (ws-proxy, no auth) → gateway (device auth, operator.write)
         → http://localhost:8080 (Vite) → gateway HTTP + filesystem endpoints
```

**chatCompletion flow (openclaw.ts):**
1. `sessions.send` — sends message, returns `{ runId, status, messageSeq }`
2. `agent.wait` — polls until agent run finishes, returns `{ status: "ok"|"error"|"timeout" }`
3. `sessions.get` — fetches last N messages from session
4. Extracts last assistant message text — format: `{ type: "text"|"thinking"|"toolCall", text: "...", thinking: "..." }`

**Key insight:** `sessions.send` params = `{ key, message, idempotencyKey }` — NOT `messages[]` array. Response from `agent.wait` only contains `{ runId, status, endedAt }` — no content. Actual response comes from `sessions.get` and is stored in `content` field as array of message objects.

**Files changed:**
- `ws-proxy.cjs` — the proxy (new file, committed)
- `src/lib/openclaw.ts` — WebSocket client + proper sessions.send/agent.wait/sessions.get flow
- `vite.config.ts` — removed broken Vite-plugin WS code, kept HTTP filesystem endpoints
- `start.sh` — starts ws-proxy then Vite dev server
- `package.json` — added `ws` package

**Status:** Fully working. Test confirmed: sessions.send → agent.wait → sessions.get → extracts assistant text.
